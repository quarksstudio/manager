# Quark Registry UI

Single Astro (SSR) application with two packaging targets that share the same
UI, pages and React islands:

| Target                      | How it runs                                                                                            | Data                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| **ServerRender (web)**      | `node dist/apps/ui/server/entry.mjs` (Astro `@astrojs/node` standalone)                                | Server-rendered: registry fetches in the page frontmatter, session cookie, metadata POST, download proxy, auth routes |
| **ClientRender (Electron)** | `apps/ui/desktop/main.cjs` embeds the same entry with `RENDER_MODE=client` and opens a `BrowserWindow` | Client-rendered islands fetch from `REGISTRY_API_URL` via `createRegistryClient`                                      |

The pages branch on `process.env.RENDER_MODE`: `ssr` (default) renders
`PackageDetails client:load` with server props; `client` renders
`PackagesBoundary` / `LandingBoundary` as `client:only` islands. Both outputs
hydrate islands.

## Prerequisites

- Node 24 and pnpm 11 (`pnpm --version`).
- A running registry API. Locally: `docker compose up` inside the Server repo
  (API on `http://localhost:8081/v1`).

## Run

```sh
# Development server (Astro, RENDER_MODE default ssr)
pnpm --filter @quarks.studio/ui-app dev

# Build the SSR bundle once
pnpm --filter @quarks.studio/ui-app build

# Serve the built web app (ServerRender)
REGISTRY_API_URL=http://localhost:8081/v1 \
WEB_ORIGIN=http://localhost:4200 \
node dist/apps/ui/server/entry.mjs

# Open the desktop client (ClientRender, RENDER_MODE=client)
pnpm --filter @quarks.studio/ui-app desktop

# Re-package the Electron app (AppImage / nsis / dmg)
pnpm --filter @quarks.studio/ui-app desktop:pack
```

Environment used at runtime:

- `REGISTRY_API_URL` — registry base URL (default `http://localhost:8081/v1`).
- `RENDER_MODE` — `ssr` (web) or `client` (Electron); set by the desktop shell.
- `WEB_ORIGIN` — public origin for `security.allowedDomains` (optional).
- `QUARK_ENV`, `FIREBASE_AUTH_EMULATOR_HOST` — local auth emulator (see `src/pages/auth/local.ts`).

## Layout and styles

`src/layouts/Layout.astro` owns the document shell (`<html class="dark">`);
`src/styles.css` imports `@quarks.studio/ui/web/styles.css`, and
`public/antd.css` holds the extracted Ant Design dark theme
(generated by `node tools/build-web-antd-css.mjs` from the library source).

## Tests

```sh
node --test apps/ui/test/astro-build.spec.mjs   # SSR build + RENDER_MODE=client shells
node --test apps/ui/test/ssr.spec.mjs           # full server flow against a fake registry API
```
